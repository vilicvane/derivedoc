# 人与 agent 的接口

## 给 agent 的接口以 CLI 为主

`dd ls/read/stat/write/append/rm` 直接读写文档，不用起服务、不用注册 MCP。位置参数是项目根
（默认当前目录），文档目录走 `--doc-dir`，省略时用项目里记下的那个；MCP 保留为可选的常驻
通道，不是使用前提。

## 工作区

工作区分两处：**项目根**放 `.derivedoc/`（对话记录、待审阅的改动等运行数据，也是 git 作用域），
**文档目录**放 `source/` 与 `derived/`。两者可以是同一个目录，也可以像本仓库这样项目根在仓库、
文档在 `prd/`。文档 id 相对文档目录，不因为项目根在哪而变。

项目根默认当前目录，文档目录默认 `ddoc/`——在项目里敲一个 `dd` 就能开始。文档目录记在
`.derivedoc/config.json` 里，显式给过一次（`dd --doc-dir=prd`）就以新给的为准。名字只是
约定，不是限制：项目可以像本仓库一样用 `prd/`，也可以把文档就放在项目根。

一个被 dd 管理的项目就是一个工作区。dd 以工作区为单位提供服务、注册与切换，打开过的会被记
下来，能在界面上辨认；一个页面里就能访问不同工作区，而不是每个工作区一个端口、一页。界面上
也能按「项目根 + 文档目录」把一个项目加进来。

## 审阅与提交

改动以 git 为准，只涉及 `source/` 与 `derived/` 两层；界面上能看到改动（diff）、可以暂存
（stage），提交由人确认。

审阅页的 diff 要在「与已提交版本（HEAD）比」和「与暂存区（staged）比」之间可切换；文档页里的
主 diff 不切换，固定与暂存区比。

## 对话记录

用户对话作为溯源依据保留，用来回答「source 里这条决定是谁在什么时候说的」。日志是本地缓存，
不进版本库。

## 选中内容交给 agent

用户能在文档里选中一段内容，把这个选区连同位置交给 agent，让 agent 拿到这段相关上下文。第一
版只要「agent 读得到」：选区记在项目里，agent 用 CLI 读；界面上给出提示，让用户知道这段已经
交出去了。用户说起「我选中的」时，agent 先读一次当前选区，别让它猜。

## web 保留启动空白会话的能力

MVP 阶段先不做 web 内对话，重点放在用户在 web 上的操作：操作触发通知，通知交给 agent，由 agent
完成派生更新与任务同步。

## 现在就用自己的设计文档维护自己

本仓库就是第一份 dogfood 产物：项目根在仓库，文档目录是 `prd/`。
