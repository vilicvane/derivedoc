# 产品定位与痛点

## 做给别人用

derivedoc 要交付给别人，不是自用脚本。安装、接入方式和文档约定都要能交代清楚。

## 参考 spec driven，但不写死 spec

用 source + 灵活的 derived 达成同样的目的：source 记录决定，derived 承载方案，并允许在落地
过程中调整。

## 要解决的痛点是漂移

上下文超限触发压缩时会丢细节。agent 如果没有回头查，就会凭大方向继续做；等主线做完，细节
已经和当初讨论的不一致了。

## 在全新项目中跑通完整接入

产品的完整流程要在多个全新项目中实际跑通，覆盖项目创建、初始化配置、项目级钩子与捕获链路，不能只依赖本仓库的 dogfood 状态。
