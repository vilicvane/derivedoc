# 产品定位与痛点

**落地**：[derivedoc 总览](../derived/overview.md) · [MVP 计划](../derived/mvp-plan.md)

## 决定：做给别人用的产品

不是个人自用工具。第一版就要能交代清楚安装、接入方式和文档约定，别人接得进来。

## 决定：参考 spec driven，但不接受写死的 spec

用 source + 灵活的 derived 达成同样的目的：source 记录决定，derived 承载方案并允许在
落地过程中调整。不采用「事前写死一份 spec，之后照做」的形式。

## 决定：要解决的痛点是漂移

上下文超限触发压缩时会丢细节。agent 如果没有回头查，就会凭大方向继续做；等主线做完，
细节已经和当初讨论的不一致了。
