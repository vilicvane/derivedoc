# 通知、排队与收敛

**落地**：[通知、排队与收敛](../derived/session-sync.md)

## 决定：通知只发给正在工作的会话

告知大致发生了什么更新；如果与它的工作内容相关，让它确保 derived up-to-date，并自行
决定继续原工作还是调整。空闲会话不做即时通知，改为在它下次收到用户消息时合并。

## 决定：source 变更的通知内容用行级 diff

以「该会话上次已知的版本」为基准计算。不附带额外上下文或定位信息，agent 自己决定后续
怎么读取理解。

## 决定：agent 更新 derived 要排队，一个一个来

用户权限更高：用户在 web 上更新 source 直接生效，并同步更新排队中的任务。用户消息
触发的派生任务同样排队等待，不插队。

## 决定：收敛取「先落地再排队」

文档本身就是 source of truth，偶尔偏离可以接受，也不要求 agent 随时被通知到最新版。
所以不做落地前校验，不追求 derived 永远最新。

## 决定：任务范围不预先规定粒度

用户可以写进一个文件、分散成很多文件、或者分散但用链接串起来，由 agent 灵活处理。

## 决定：MVP 不做精确覆盖追踪

不引入「每篇 derived 声明覆盖哪些 source 及版本」的机制，以后确实需要再加。
